# HopAhead implementation plan

> Agentic workers: use the execution and verification skills. Root integrates; workers own separate worktrees. User approved implementation and GitHub delivery.

**Goal:** Run an explainable Boston connection advisor from browser through Kafka and PostgreSQL, with deterministic replay and tested recovery.

**Architecture:** A collector publishes complete compressed observations as chunk/manifest records. A worker commits idempotent projection changes before Kafka offsets. A separate API owns journey commands through a transactional outbox; React consumes versioned snapshots.

**Tech Stack:** TypeScript, React, Node, KafkaJS, Apache Kafka KRaft, PostgreSQL, Vite, Node test runner, Playwright.

**Spec:** [Approved design](../specs/2026-11-05-hopahead-design.md).

## Constraints and ownership

- Curated Harvard → Park Street → Copley UI; citywide feed ingestion.
- Kafka only. One partition per source; 256 KiB chunks; database commit before offset commit.
- Pure advice with explicit time, 90-second stale threshold, 152/184-second imported transfer allowances, 120-second enough-time boundary.
- No screenshots, hidden live/replay mixing, fabricated certainty, or claim of host-loss availability.
- Shared contracts live in `src/shared/contracts.ts`; root alone changes this file, manifests and lockfile.
- Root owns API, journey persistence, Compose, documentation, integration and publication. Worker A owns `src/domain`, `src/fixtures`, domain tests; B owns stream/collector/database projection files and stream tests; C owns `src/client`, `index.html`, UI tests.
